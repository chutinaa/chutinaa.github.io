正式版教学版Excel + CSV 输入
▶
输入业务系统导出 Excel + 数据仓导出 CSV输出逐行比对结果 + 勾选后的上传文件

解决什么

  • 审批前要确认两边记录一致；原来靠人肉 VLOOKUP 四个字段，一批两百行要半天。

关键机制

  • 比对四个字段：主体 ID、客户、区域、类型；只有主体 ID 不一致叫「主体不一致」（两边说的不是同一个对象），其余三项叫「属性偏差」（同一个对象、属性填得不一样），两者处理路径不同，词也不混用。
  • 状态字段只承担一个维度（主体 ID），偏差用独立布尔位表达；排序按处理档而不是按字母，最需要动手的排最前，作废行无条件置底。
  • 默认只勾选干净行；有偏差的行要人手动确认才进导出。
  • CSV 解析支持引号内逗号，客户名含逗号不再整行错位。
兜底：缺必填材料的行默认不导出，标签标黑框提示补件；同一申请下有严重问题时，同组干净行也一起取消勾选，避免半批上传。
批量记录整理把系统页面整段复制过来，自动抠字段、识别操作类型、对账后按区域导出
正式版教学版粘贴 / Excel 输入
▶
输入系统页面整段粘贴，或按列名读 Excel输出按区域分组的上传文件

解决什么

  • 每天几十条申请要从页面一条条复制到模板，格式还不统一（制表符、竖线、空格混着来）。

关键机制

  • 不依赖列位置，按字段「形状」用正则抠：工单号、9–13 位账户号、站点代码。
  • 操作类型（锁定 / 解锁 / 改站点）按关键词出现次数识别；三种混在一起时提示拆开，不做猜测。
  • Excel 输入按列名匹配（精确优先，再部分匹配并排除干扰词），不靠列序。
兜底：页面声明的条数 vs 解析条数对账；对不上亮黄条，并按「有工单号但缺其它字段」定位疑似漏行。宁可多提示，不能默默少一条。
申请单与系统记录核对申请表里填的 ID 和系统里的记录逐条对，差异标红
正式版教学版两表输入
▶
输入系统工单导出 + 申请人提交的表格输出逐条核对结果，可直接作为审核备注

解决什么

  • 审批要确认申请表和系统记录说的是同一批对象；漏对一条就是一次返工。

关键机制

  • ID 先归一化（大小写、空格、连字符）再比，减少格式噪音带来的误报。
  • 结果三色：一致 / 需人工确认 / 系统中不存在；每条写明差在哪。
兜底：两表条数不一致先提示，不直接出结论；未找到的 ID 单列一组，避免混在「主体不一致」里被忽略。
跨站点字段转换批量修改站点字段，并按目标平台拆成各自的上传文件
正式版教学版多平台输出
▶
输入待修改记录清单输出按平台拆分的多个上传文件

解决什么

  • 不同平台的上传模板不同，同一批修改要手工分成几份、各自调格式。

关键机制

  • 保留原始列，派生列另起，不覆盖原值，方便回查。
  • 按平台规则自动分组，每组生成一份文件，文件名带平台与日期。
兜底：分组后总行数必须等于输入行数，不等就拒绝导出并指出差在哪一组。

Hub 与共同设计原则

入口一张 Hub 页收口全部工具，分「常用」「其他」两组；每张卡有正式版和教学版两个入口，页脚写清「共 N 个工具 · 全部支持离线」。
形态每个工具一个 .html 单文件，双击即开；表格库、样式、图标全部内嵌，公司网络断外网也能用。
教学版与正式版同一份源码，靠一个开关多出讲解层和示例数据；改逻辑只改一处，两版永远一致。
术语每个状态词只指一件事（例如「主体不一致」只指主键冲突，属性差异另有其名），文案改动前先 grep 全部测试，区分「断言描述」与「判据」。
兜底每个工具都有一条对账恒等式（条数、行数、总额其一）；对不上就拦，不默默放过。
验证无头浏览器跑回归；改文案、改口径后先跑再交。改动附备份、字节数与特征串对拍。
为什么是 HTML 而不是脚本或插件：团队成员没有管理员权限、不能装软件，也不该为了用一个工具先学环境配置。一个文件谁都能双击打开，复制到别的电脑也一样。技术选型服从使用场景，这是这六个工具唯一没变过的决定。
