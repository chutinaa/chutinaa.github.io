⑤ How it is built demo vs production, separately

This demo pagePure in-browser JavaScript, single-file HTML, zero dependencies, zero network requests. The demo does not really run OCR: the scan's text is a preset fictitious recognition result (with O/0 and I/1 misreads left in on purpose) to show how the judging rule shifts with the source.
RuntimeProduction: a local HTTP server on Bun plus a single-page front end; starts from a double-clicked .bat, all relative paths, the whole folder copies to a colleague as-is.
Word direct readHand-written zip central-directory parsing + zlib.inflateRaw to unpack word/document.xml and every header and footer, taking native characters: 3–8 ms, zero recognition error. No Office dependency, no PowerShell (dodging its encoding traps).
PDF / scansScribe.js first rasterises the PDF to PNG (Windows ships no scriptable PDF renderer); it rasterises only, it never OCRs.
OCR engineWindows built-in OCR (Windows.Media.Ocr), invoked via PowerShell + WinRT reflection (System.Runtime.WindowsRuntime supplies AsTask for a synchronous call). Fully offline, nothing to install, no admin rights, zero cost, about 0.5–0.6 s per page, with the en-US and zh-Hans-CN language packs installed.
MatchingEach line is stripped of all non-alphanumerics, then a tolerant substring search (OCR drops commas and spaces into the middle of IDs, so regex candidate-splitting is out); only 5 genuinely inseparable glyph groups count as equal: 0/O/D 1/I/L/T 2/Z 5/S 8/B. Every other difference scores — better a few extra needs-review rows than a single false match.
Regression baselineReal data, 86 IDs → 76 matched / 8 needs review / 2 not found; 0% false positives on 5,000 random IDs.
Why no cloud LLM, and no Tesseract: the documents hold confidential information and there is no compliant channel to send them to an external model, so local is the only viable option; a review scenario demands reproducible, auditable judgments — non-deterministic LLM output is inherently unfit. Measured: Tesseract / Scribe.js took 53 s for 4 pages, the built-in OCR 2.3 s, and the former's WASM + Worker only runs behind an HTTP server.
Judging rule: Word direct read = trusted text, only an exact character match passes; one character off goes to needs-review. OCR = the machine may misread, so common confusions (O/0, I/1…) are auto-tolerated; every other difference still goes to needs-review. Demo · single-file HTML · works offline
